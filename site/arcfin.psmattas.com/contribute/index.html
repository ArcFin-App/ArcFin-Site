Contributing code

Pull requests are welcome. Start with CONTRIBUTING.md for how to build and the project’s conventions, and ARCHITECTURE.md for how the app fits together. Issues labelled Good First Issue say which file to start in and what “done” looks like.

  • Sign off every commit. Arcfin uses the Developer Certificate of Origin. Commit with git commit -s to add the Signed-off-by: line. There’s no CLA and no copyright assignment; you keep the copyright on your work.
  • Make text translatable. New text in the app goes into the String Catalogs in the same pull request.
  • Follow the Code of Conduct.

Translating Arcfin

Arcfin is available in English, German, French, Spanish, Simplified Chinese, Brazilian Portuguese, Japanese, Italian, Korean, Dutch and Russian. The first ten translations were machine made and need native speakers to check them.

To fix a translation or add a language, open a Translation issue. The translation guide explains how.

AI-assisted development

Arcfin is written by one developer with help from AI coding tools. The AI writes code to specifications the maintainer defines; it doesn’t decide the architecture, the design or what gets built. Every change is read and tested by the maintainer before it merges, and the maintainer is responsible for everything that ships. Contributors can use AI tools too, under the rules in CONTRIBUTING.md.

Forks and the Arcfin name

The code is free to fork under the AGPL-3.0. The Arcfin name, logo and app icon aren’t covered by the code license, so a fork needs a name and icon of its own. See TRADEMARK.md.

Prefer email?

For anything that doesn’t fit the issue tracker: contribution.arcfin@psmattas.com. Please don’t send passwords, server tokens or other private details. Security problems go to security@psmattas.com.
