Contribuire al codice

Le pull request sono benvenute. Inizia da CONTRIBUTING.md per compilare e conoscere le convenzioni del progetto, e da ARCHITECTURE.md per capire come è fatta l’app. Le issue con l’etichetta Good First Issue dicono da quale file partire e cosa significa “finito”.

  • Firma ogni commit. Arcfin usa il Developer Certificate of Origin. Fai il commit con git commit -s per aggiungere la riga Signed-off-by:. Niente CLA né cessione dei diritti; il copyright sul tuo lavoro resta tuo.
  • Rendi il testo traducibile. Il nuovo testo dell’app va negli String Catalogs nella stessa pull request.
  • Rispetta il codice di condotta.

Tradurre Arcfin

Arcfin è disponibile in inglese, tedesco, francese, spagnolo, cinese semplificato, portoghese brasiliano, giapponese, italiano, coreano, olandese e russo. Le prime dieci traduzioni sono state fatte automaticamente e servono madrelingua che le controllino.

Per correggere una traduzione o aggiungere una lingua, apri una issue di tipo Translation. La guida alla traduzione spiega come fare.

Sviluppo assistito dall’IA

Arcfin è scritto da un solo sviluppatore con l’aiuto di strumenti di IA. L’IA scrive codice secondo specifiche definite dal maintainer; non decide l’architettura, il design o cosa costruire. Ogni modifica viene letta e testata dal maintainer prima di essere integrata, e il maintainer è responsabile di tutto ciò che viene rilasciato. Anche chi contribuisce può usare strumenti di IA, secondo le regole di CONTRIBUTING.md.

Fork e il nome Arcfin

Il codice si può forkare liberamente secondo la AGPL-3.0. Il nome, il logo e l’icona di Arcfin non sono coperti dalla licenza del codice, quindi un fork ha bisogno di nome e icona propri. Vedi TRADEMARK.md.

Preferisci l’email?

Per tutto ciò che non rientra nel tracker delle issue: contribution.arcfin@psmattas.com. Non inviare password, token del server o altri dati privati. I problemi di sicurezza vanno a security@psmattas.com.
