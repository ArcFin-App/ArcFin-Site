Contribuir com código

Pull requests são bem-vindos. Comece por CONTRIBUTING.md para compilar e conhecer as convenções do projeto, e por ARCHITECTURE.md para entender como o app se encaixa. Issues com o rótulo Good First Issue dizem por qual arquivo começar e o que significa “pronto”.

  • Assine cada commit. O Arcfin usa o Developer Certificate of Origin. Faça commit com git commit -s para adicionar a linha Signed-off-by:. Não há CLA nem cessão de direitos autorais; os direitos sobre seu trabalho continuam seus.
  • Deixe o texto traduzível. Texto novo no app vai para os String Catalogs no mesmo pull request.
  • Siga o Código de Conduta.

Traduzir o Arcfin

O Arcfin está disponível em inglês, alemão, francês, espanhol, chinês simplificado, português do Brasil, japonês, italiano, coreano, holandês e russo. As dez primeiras traduções foram feitas por máquina e precisam de falantes nativos para revisá-las.

Para corrigir uma tradução ou adicionar um idioma, abra uma issue do tipo Translation. O guia de tradução explica como.

Desenvolvimento com ajuda de IA

O Arcfin é escrito por um desenvolvedor com a ajuda de ferramentas de IA. A IA escreve código conforme especificações definidas pelo mantenedor; ela não decide a arquitetura, o design nem o que é construído. Cada mudança é lida e testada pelo mantenedor antes de ser integrada, e o mantenedor é responsável por tudo o que é lançado. Colaboradores também podem usar ferramentas de IA, seguindo as regras do CONTRIBUTING.md.

Forks e o nome Arcfin

O código pode ser bifurcado livremente sob a AGPL-3.0. O nome, o logotipo e o ícone do Arcfin não estão cobertos pela licença do código, então um fork precisa de nome e ícone próprios. Veja TRADEMARK.md.

Prefere e-mail?

Para o que não couber no rastreador de issues: contribution.arcfin@psmattas.com. Não envie senhas, tokens do servidor nem outros dados privados. Problemas de segurança vão para security@psmattas.com.
